# A-Team · 轻量智能体流水线

一套**单机、本地优先**的智能体流水线系统。在可视化画布上把智能体连成一张流程图：每个智能体是一个节点，节点之间用带箭头的线交接。任务从起点节点进入，每个环节交付**一个文件夹**，系统整目录复制给连线指向的下游，并用连线上的「任务触发提示词」自动启动它；终点节点的交付文件夹交给你验收。

- **B/S 架构**：React + Vite 前端，Node.js + Express 后端
- **技术栈**：Node.js 24 · TypeScript · React 18 · React Flow 画布 · SQLite（Node 内置 `node:sqlite`）
- **无需沙箱**：所有智能体工具与命令都在本机执行
- **真实模型驱动**：通过 OpenAI Chat Completions 兼容协议接入 DeepSeek、OpenAI、通义等真实模型

---

## 核心模型

```text
画布：   [产品经理] ──▶ [架构师] ──▶ [开发] ──▶ [审核] ──▶ [交付终点]
            ▲──────────── 返工（带交接条件）───────────┘
每根带箭头的连线 = 交接规则：
  · 任务触发提示词（必填）：上游交接后，系统替换占位符并作为下游的第一条用户消息注入
  · 交接条件（多出边时必填）：写进上游智能体的系统提示词，指导它用 target 选择交给谁
```

- **节点即智能体**：一条流水线内每个智能体最多出现一次；没有独立的「环节名称 / 职责」概念，岗位信息由智能体档案 + 连线提示词承担。
- **起点**：画布上显式标记的节点（全流水线恰好一个），用户任务直接交给它；起点也可以接收返工连线。
- **终点**：没有出线的节点。它的交付文件夹被复制到任务目录 `final/`，任务进入「等待验收」。
- **交付单元 = 文件夹**：handoff 工具只接收 `folder`（+ 多出边时的 `target`）。系统把整个文件夹递归复制到接收方 `inbox/<发送方slug>/…`，同名时**整个目录**加 `-v2` 后缀，绝不覆盖。
- **交接条件**：某节点有 ≥2 条出线时，每条出边都必须写「什么情况下交给谁」；这些条件注入该节点智能体的系统提示词，交接时由智能体判断并用 `target` 指明目标。
- **暂停**：某环节失败、超时或没有产生有效交接（含判定不出该交给谁）时，任务停在这一环节（`paused`），由用户决定「重试本环节」或「终止任务」。

## 功能

### 流水线
- **React Flow 可视化画布**：智能体为节点、带箭头的连线为交接规则；节点可拖动（坐标持久化保存），连线携带「任务触发提示词」，多出边时另填「交接条件」。
- 一条流水线最多 30 个节点、300 条连线；同一个智能体只能是一个节点。
- 任务启动时保存流水线**快照**：之后修改或删除流水线，不影响进行中与历史任务。
- 删除仍在使用的智能体或仍有活动任务的流水线会被拒绝。

### 智能体
- 岗位提示词：任务说明（必填）、交付要求、工作指南；运行时自动追加流水线定位、本环节任务、出边交接条件、工作区、工具与技能。
- 模型覆盖、温度、最大 ReAct 轮数。
- 常驻资料区 `workspaces/<agent-slug>/`；任务内独立工作区 `workspaces/tasks/<任务ID>/<agent-slug>/`。
- **内置工具统一授予**：所有内置工具（含 `handoff`、`submit_feedback`；`load_skill` 需配置技能后出现）由系统强制授予每个任务型智能体，不再按智能体裁剪——流水线跑的是开放式任务，充分放开模型能力。`handoff` 是环节间交接专用工具，只注入给流水线环节；设计师没有任务与交付，不注入 handoff。自定义 JavaScript 工具仍按智能体勾选（档案里的内置工具开关字段保留但已不生效）。
- 技能包（Markdown 说明书 + 脚本 + 素材）按需 `load_skill`。

### 工具体系（对齐 DeepSeek Harness）
内置通用工具命名与语义对齐 DeepSeek Harness，**统一授予所有智能体**；`bash` / `pwsh` 按平台可用性注册（缺哪个 shell 就不注册哪个），`load_skill` 只在智能体配置了技能时出现：

| 工具 | 说明 |
| --- | --- |
| `bash` / `pwsh` | 在全新 shell 进程中执行一条命令（bash 检测到 Git Bash 时可用；Windows 上 pwsh 恒可用）。每次调用不保留上一次的变量与工作目录，用 `workdir` 指定目录；命令超时会被终止，退出码非零属正常结果 |
| `read` / `write` / `edit` | 读取（带行号、可分页）/ 原子写入（整文件替换）/ 字面量精确替换。**覆盖或修改前必须先 `read`**：系统按回合登记读取观测，未读先改（`FS_NOT_OBSERVED`）或读取后被外部改动（`FS_STALE_VERSION`）都会被拒绝 |
| `glob` / `grep` | 按文件名 glob 查找（按修改时间倒序，最多 100 条）/ 按正则搜索内容（按文件分组，最多 250 条）。跳过依赖、构建产物与 VCS 目录 |
| `list_dir` | 递归列目录（本系统的扩展工具，DeepSeek Harness 没有） |
| `read_image` | 读取本地图片（PNG/JPEG/GIF/WebP，按文件签名识别）并把图像本身作为多模态内容发给模型，需要多模态模型 |
| `web_search` | 联网搜索（DeepSeek 搜索 API，按成功请求计费）：一次 1-4 条查询，合并去重后返回来源 URL 与摘要 |
| `web_fetch` | 本机直接抓取 HTTP(S) 网页并转为 Markdown（免费、可访问内网）：仅同源重定向、不携带凭据，结果标记为不可信外部数据 |

错误以稳定错误码返回（如 `FS_NOT_FOUND`、`FS_AMBIGUOUS_EDIT`、`WEB_PROVIDER_UNAVAILABLE`），并附恢复建议。命令输出超长时保留尾部（报错现场通常在尾部）。流水线专属工具 `handoff`、`load_skill`、`submit_feedback` 保持不变。

### 流水线设计师
- **对话式系统管理员**：「设计师」页与内置的流水线设计师对话，描述你想自动化的流程；它拥有全局视角（系统清单自动注入提示词），能查看所有智能体、流水线、工具、技能与反馈。
- **详情入口**：聊天头部一键查看设计师详情——实时拼装的完整系统提示词（含系统清单、任务型智能体的工作模式、流水线运作方式、试运行与迭代方法、设计要领与工作规则，与模型每次请求实际收到的一致）、实际生效的工具清单（统一授予的内置工具 + 设计师专属管理工具）、启用的技能包；并附「去智能体页编辑」跳转。
- **会话信息**：聊天头部常驻展示当前模型、深度思考级别与上下文使用量/总量（口径：最近一次模型请求的真实输入 + 输出 token，与上下文压缩判断同口径；总量取设置中的最大上下文长度）。
- **思考与工具调用透明**：助手消息展示模型的思考内容（`designer.reasoning` 流式推送，默认折叠成单行，点击展开全文）；工具调用 chip 与工具结果行都会带参数摘要（如 read 了哪个文件），展开工具行可看完整参数 JSON 与结果。
- **对话附件**：输入框支持直接粘贴图片、选择文件或拖拽上传（单文件 ≤ 20 MB，一条消息 ≤ 10 个附件）。所有附件（含图片）保存在设计师工作目录 `uploads/<会话>/` 下，消息自动附上路径清单，由设计师用 `read` / `read_image` 工具自行读取；消息气泡中可预览图片、下载文件。删除会话会一并清理该会话的上传目录。
- **对话式变更（认可即执行）**：协作节奏是「提问澄清 → 设计思路 → 认可即执行」，全程对话完成、无需点击任何确认按钮。需求有疑问时设计师先提问；需求清晰后它简明讲出设计思路，你认可后它立即调用 `apply_changes` 一次性应用**结构化变更**（新建/修改/删除智能体、流水线、自定义工具、技能），系统按清单顺序原样执行并留下变更记录卡片；执行中断时已生效项保留、卡片回显失败原因与进度。同一次变更内「先创建、后引用」按变更顺序解析：后项可直接引用前项新建的技能、智能体、工具（引用后序才创建的对象、先建后删、先删后引都会在校验期被拒绝并给出定位提示）。
- **边界保护**：内置工具对任务型智能体统一授予、只读不可删改；设计师不注入 `handoff`（无任务工作区与交付，运行时和详情工具清单都会过滤它，防止模型反复调用形成死循环）。设计师不能通过 `apply_changes` 修改或删除它自己（其定义由人类在「智能体」页维护）；不能被加入流水线节点、不能被删除；删除在用对象仍受现有校验保护。
- **专属工作目录**：`workspaces/designer/` 为系统级目录（不属于任何任务），存放它的设计草稿、工作产物与会话附件；「一键清空」会清掉它的会话、变更记录与该目录，但保留设计师本身。
- **运行记录与试运行**：试运行由用户在「任务」页发起；设计师可用 `list_tasks` 查看任务列表与状态、用 `get_task` 复盘一次任务的环节链路与每环节输入/输出/交接/错误（可再按环节细看系统提示词与消息记录），据此向你说明问题并给出修正思路。
- **反馈闭环**：设计师可用 `list_feedback` 读取智能体提交的反馈（传 id 看全文与上下文快照），把有价值的踩坑与建议转成改进思路，与你达成一致后直接执行，再用 `resolve_feedback` 标记已处理/忽略，形成「踩坑 → 反馈 → 改进 → 关闭」的完整闭环。

### 智能体训练师
- **单智能体教练**：「训练师」页与内置的智能体训练师对话，从 0 打造并持续训练**单个**智能体。交互与设计师完全一致：流式回复、附件、详情抽屉、工作目录、变更卡片。训练师没有系统级视野——工具与提示词都不注入系统清单，看不到其他智能体与流水线的全貌；要训练谁由用户指定，已有智能体用 `get_agent` 查看当前定义（系统角色不可查）。
- **提示词从 0 写**：训练师创建的智能体，提示词完全从 0 撰写（不套用现有格式），且必须明确写清三件事——接收哪些输入、职责与工作目标、交付要求；所有智能体默认自动携带全部内置工具（不可删除修改），训练师可配置的是提示词、自定义工具、技能、模型与温度。
- **训练三规则**：① 新建或修改智能体前先向用户讲清调整思路与关键设计，认可后再 `apply_changes`（只含智能体/自定义工具/技能 9 种变更）；② 每次变更生效后立即用 `start_test_task` 启动一轮测试任务；③ 任务停在「等待用户验收」后请用户到任务页评审交付物并给反馈，按反馈优化后进入下一轮，直到用户满意。
- **测试任务**：`start_test_task` 给目标智能体发起单环节测试任务，跑完等待用户验收；系统内部用「智能体训练台」承载（用户无需关心），任务启动时固化快照，之后对智能体的修改不影响进行中与历史记录。同一时间只允许一个活动任务，被拒时训练师会引导你先验收或终止；`stop_test_task` 可终止跑偏的测试。
- **视野收窄的任务工具**：`list_tasks` / `get_task` 只能看到训练师自己启动的测试任务（其他任务不在其视野内）；可按环节查看测试任务实际下发的系统提示词与完整消息记录，用于复盘与定位问题。
- **专属工作目录**：`workspaces/trainer/`（系统级，存训练记录与草稿）；「一键清空」会清掉训练师的会话、变更记录与该目录。训练师是系统角色，不能通过对话变更修改或删除（包括它自己）。

### 技能包
- 一个技能是一个目录包：`SKILL.md` 说明书 + `scripts/` 脚本 + `assets/` 素材；编辑器中可直接新建、上传、重命名和删除文件，Markdown 与脚本均带语法高亮。
- 脚本统一放在 `scripts/` 下，**同一技能内脚本文件名不能重复**（不区分大小写），文档才能无歧义地引用。
- 编辑说明书时点「插入脚本」，会在光标处插入 `'{{script:文件名}}'`；`load_skill` 时系统把技能包复制到智能体任务工作区的 `.skills/` 下，并把占位符替换成脚本的绝对路径。
- 脚本改名会自动同步文档中的占位符；删除仍被文档引用的脚本会被拒绝。
- 单个文件最大 512 KB，单个技能总量最大 4 MB、最多 100 个文件；脚本必须以 UTF-8 文本保存，其他素材支持二进制上传。
- 脚本由智能体用 `bash` / `pwsh` 执行。Node.js 随应用可用；Python 等运行时需要本机已安装。`.skills/` 是系统管理的只读副本，不能作为交付物提交。

### 任务与交付
- 发起任务时只需选择流水线并填写任务描述；任务原文直接作为起点环节的用户消息。
- 下游每个环节的用户消息 = 所在连线的**任务触发提示词**（系统替换 `{deliverables}`＝交付目录在其工作区的路径、`{task}`＝原始任务、`{sender}`＝上游智能体名；未识别的 `{xxx}` 原样保留），除此之外不注入任何模板内容——想传达的说明请写成交接文件夹里的文件。
- handoff 工具只接收 `folder`（一个目录）；有多个交接对象时加 `target`（目标智能体名称）。
- 终点环节交付的文件夹整体复制到 `workspaces/tasks/<任务ID>/final/`，用户可在页面上浏览文件夹、预览文本 / 图片 / PDF 或下载文件。
- 暂停后可「重试本环节」：追加新的一个环节，不修改历史记录，可附补充指示。

### 示例流水线
- 「一键加载示例流水线」会创建策划 / 执行 / 审校三个智能体和一条三步流水线，可作为起步模板直接改造使用。

### 反馈与清理
- 智能体遇到不合适的提示词、工具、技能或流程，或希望系统补充某个工具、对系统或上下游智能体提出建议时调用 `submit_feedback`，系统附带任务、回合、系统提示词与最近上下文。
- 流水线设计师可以读取这些反馈（`list_feedback`，传 id 可看全文与上下文快照），在对话中与你讨论后转成改进思路，经你认可后直接执行，并用 `resolve_feedback` 关闭已处理的反馈，形成「踩坑 → 反馈 → 改进 → 关闭」的闭环。
- 一键清空会删除任务、回合、对话、设计师会话与变更记录、设计师工作目录；保留智能体（含设计师本身）、流水线、工具、技能与反馈。

## 快速开始

### 环境要求
- Node.js **24+**（使用内置 `node:sqlite`）
- pnpm 8+

```bash
pnpm install
pnpm dev
```

打开 **http://127.0.0.1:5310**（Vite 会把 `/api` 代理到 `3310`）。

> 端口说明：A-Team 默认使用 **Web 5310 / API 3310** 专属端口段，
> 避免与其他并行开发的本地项目（如 3000 / 5173 等常见默认端口）冲突；
> 且 `strictPort` 开启——端口被占用时 Vite 直接报错退出，不会静默漂移到其他端口。

生产模式：

```bash
pnpm build
pnpm start
```

打开 **http://127.0.0.1:3310**。

### 自动部署到云服务器（端口 3002）

采用「开发机编排 + 服务器 `git pull`」模式：**推送代码 → 服务器拉代码 → 装依赖 → 构建 → 重启 → 健康检查 → 公网冒烟测试**，任一步失败自动回滚到上一个版本。

A-Team 直接监听 `0.0.0.0:3002` 对外提供服务，**不装 nginx、不占用 80 端口**，可与同机的其他服务（例如占用 80 的 CloudNine）共存。

| 脚本 | 运行位置 | 作用 |
| --- | --- | --- |
| `scripts/deploy_ateam.py` | 开发机 | 编排器：可选 push → SSH 引导/部署 → 公网健康检查 → 冒烟测试 |
| `scripts/bootstrap.sh` | 服务器（root） | 首次引导：Node 24 / pnpm / 服务账号 / systemd / 构建启动 |
| `scripts/deploy_remote.sh` | 服务器 | 日常部署：拉代码、构建、重启、健康检查、失败自动回滚 |
| `scripts/smoke_test.py` | 任意 | 只读 API 冒烟测试（不会写入任何数据） |
| `scripts/systemd/ateam.service` | 模板 | systemd unit，由 `bootstrap.sh` 注入真实路径 |

#### 首次部署

```bash
# 0. 前提：改动已提交（部署脚本本身也必须在仓库里，--push 会负责推上去）
git add -A && git commit -m "..."

# 1. SSH 凭据，任选一种：
#    a) 密钥（推荐）：~/.ssh/id_ed25519 会被自动发现，或显式 --key <path>
#    b) 密码：在 .secrets/aliyun.env 写 export SSH_PASSWORD=...（或 CN_SSH_PASS），
#       也可直接交互输入；密码登录需要本机安装 sshpass
#       同一个文件也能写 ATEAM_DEPLOY_HOST / USER / DIR / PORT 覆盖默认目标
# 2. GitHub 推送凭据：.secrets/github.env 里的 GITHUB_TOKEN（scripts/push.py 读取）
pnpm deploy:bootstrap --push
```

#### 日常部署

```bash
pnpm deploy:prod --push        # 推代码 + 部署 + 冒烟测试
pnpm deploy:prod               # 只部署服务器上的最新 origin/main
pnpm deploy:prod:skip-build    # 不重新构建，仅重启（改了服务器配置时用）
pnpm deploy:smoke --url http://8.159.144.112:3002/   # 单独跑冒烟测试
```

> pnpm 会把参数直接转发给脚本，**不要加 `--`**（pnpm 8 会把 `--` 原样传给 Python 导致参数解析失败）。
> 也可以直接调用：`python3 scripts/deploy_ateam.py --host 1.2.3.4 --user ubuntu --key ~/.ssh/id_ed25519 --no-build --skip-smoke`

#### 常用参数

#### 部署细节

- 部署目录 `/opt/ateam`，服务账号 `ateam`，服务名 `ateam`：`systemctl status ateam`、`journalctl -u ateam -f`。
- 运行参数在 `/etc/ateam/ateam.env`（`PORT=3002`、`HOST=0.0.0.0`），首次引导生成后不会覆盖。
- **不丢数据**：`data/`（SQLite）与 `workspaces/`（任务工作区）是 gitignore 的持久化目录，拉代码和回滚都不会删除；旧版 SFTP 部署的实例可直接用 `--bootstrap` 平滑升级。
- **失败自动回滚**：代码退回 `PREV_COMMIT` 并重新构建、重启服务，日志见 `journalctl -u ateam`。
- 首次部署后需在云控制台放行 `3002/tcp`，否则公网健康检查会失败（此时服务器本机服务已正常）。
- 旧版「本地构建 + SFTP 上传」脚本保留为 `pnpm deploy:legacy`（`scripts/deploy.py`，依赖 `paramiko`），仅作备用。

### 首次使用
1. 在「设置 → 模型接入」填写 Base URL、模型名称与 API Key（默认指向 DeepSeek）。
2. 在「智能体」创建至少两个角色，或点任务页的「一键加载示例流水线」；也可以直接在「设计师」页对话，让它帮你搭建：它先问清需求、讲明思路，你认可后直接生效。
3. 在「流水线」画布上把智能体连成流程：标记唯一起点，每条连线填「任务触发提示词」（多出边时再填交接条件）；没有出线的节点就是终点。
4. 在「任务」选择流水线、填写任务并启动；真实模型会在每个环节产出交付文件并整目录交接、自动推进。
5. 流水线跑完后在 final 目录预览最终交付物，点「验收完成」结束任务。

## 架构

```text
ateam/
├─ server/src/
│  ├─ index.ts          # Express 启动、静态资源、优雅退出
│  ├─ config.ts         # 路径、端口、默认设置
│  ├─ db.ts             # node:sqlite 连接、schema 与增量迁移
│  ├─ store.ts          # 数据访问、流水线图校验、任务与回合
│  ├─ runtime.ts        # 连线推进、触发提示词注入、ReAct 循环、暂停与重试
│  ├─ designer.ts       # 流水线设计师：对话驱动运行时、管理工具族、变更执行器
│  ├─ handoff.ts        # 交付文件夹整目录复制与同名自动加版本
│  ├─ prompt.ts         # 系统提示词拼装（含流水线定位与交接条件）
│  ├─ tools.ts          # 内置工具（对齐 DeepSeek Harness）、自定义 JS 工具、技能加载
│  ├─ web-tools.ts      # web_search（DeepSeek 搜索 API）与 web_fetch（本机抓取）
│  ├─ html-text.ts      # HTML → Markdown 转换器（web_fetch 专用，无第三方依赖）
│  ├─ llm.ts            # OpenAI 兼容客户端（含多模态消息）
│  ├─ events.ts         # SSE 事件总线
│  └─ routes/           # REST API
├─ shared/types.ts      # 前后端共享类型与流水线图工具函数
├─ web/src/             # 页面、组件、API 客户端、样式（流水线编辑器基于 @xyflow/react）
├─ tests/               # Vitest 集成测试
└─ data/                # 运行时生成：SQLite
```

### 数据表
`settings`、`agents`、`pipelines`（nodes + edges JSON）、`tasks`、`turns`、`conversations`、`messages`、`feedback`、`designer_sessions`、`designer_messages`、`designer_proposals`。

### 状态
- **任务**：`running` → `paused` → `running` → `waiting_human` → `completed` / `aborted`；无法继续时 `failed`。
- **回合**：`running` → `completed` / `failed` / `aborted`。

### ReAct 循环
1. 组装系统提示词（含流水线定位、出边交接条件）、历史消息、启用的工具。
2. 调用模型。
3. 有工具调用则依次执行并写回上下文。
4. 无工具调用则返回文本；没有 `handoff` 视为本环节失败，任务暂停。
5. `handoff` 提交（folder + 多出边时的 target）后立即结束本环节：整目录复制到目标（或 final），渲染目标连线的触发提示词并启动下一环节。
6. 每轮都写入 SQLite，前端通过 SSE + React Query 刷新。

## 已知边界

- **schema 升级保留业务数据**：数据库结构版本升级不再清空数据。`server/src/db.ts` 中的 `MIGRATIONS` 逐版本执行增量迁移（事务保护，失败回滚并拒绝启动，绝不静默清数据）；只有迁移基线（v9）之前的探索期旧库才按旧策略清空业务表（保留 `settings`）。发布涉及结构变更的新版本时，记得把 `SCHEMA_VERSION` 加一并在 `MIGRATIONS` 追加对应升级步骤。
- web_fetch 可访问本机与内网地址（本地单机工具的合理需求），网页结果会标记为不可信外部数据；如部署到不受信网络请自行增加出口代理或防火墙规则。
- 单进程、单用户；没有登录鉴权，默认只监听 `127.0.0.1`。如果把 `HOST` 改为 `0.0.0.0`，本机命令执行能力会暴露给网络，请自行加反向代理鉴权。
- 同一时间只允许一个未结束的任务（执行中 / 已暂停 / 等待验收）；需先处理或终止。
- 流水线按连线推进，不支持并行分支：一个环节只会交给一个交接对象；返工通过把连线指回上游节点实现（返工环下起点靠显式标记）。
- 任务启动后使用流水线快照，编辑或删除流水线不会影响进行中的任务。
- 人工只能验收或重试，不能编辑智能体产出。
- 服务重启时，执行中的任务会停在当前节点并标记为暂停，可重试或终止。
- API Key 以明文保存在本机 SQLite 中，仅适用于可信的单机环境。
- 使用 Node 内置 `node:sqlite`，启动时可能出现 ExperimentalWarning，属正常现象。
- 自定义工具没有沙箱隔离，请只运行你信任的代码。
